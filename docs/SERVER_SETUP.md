# Серверная CRM без Hoster

## Что реализовано в коде

Next.js + TypeScript как сервер приложения, существующий интерфейс и бизнес-правила переиспользованы. PostgreSQL подключается через `pg`. Prisma пока не добавлена: первая серверная модель хранит CRM в одном JSONB-агрегате, чтобы перенести весь существующий сценарий без двух расходящихся моделей. Учётные записи, сессии, ограничения входа и идентификаторы операций находятся в отдельных таблицах.

Каждая команда выполняется в транзакции с блокировкой строки рабочего пространства. Версия защищает от потери параллельных изменений; при конфликте пользователь обновляет данные и повторяет действие. Ответ содержит только записи, разрешённые роли. Вход использует хеш пароля scrypt, случайную сессию, HttpOnly cookie, срок 12 часов и ограничение попыток. Публичной регистрации и переключателя роли в серверном режиме нет. Идентификатор сотрудника берётся из сессии, а не из запроса.

Это первая модель для небольшой команды и синтетических данных. Общая блокировка ограничивает масштабирование. Перед реальными клиентскими данными нужны нормализация таблиц, проверка всех сценариев с PostgreSQL, резервное копирование, восстановление доступа и согласование размещения. Документы пока остаются чек-листом, файлы не загружаются. Приглашения и сброс пароля по почте ещё не реализованы. Изменения других сотрудников загружаются кнопкой «Обновить данные», автоматической синхронизации пока нет.

## Локальный запуск

1. Установить зависимости: `npm ci`. Использовать Node.js 22.
2. Скопировать `.env.example` в `.env.local`, заполнить `DATABASE_URL` и `APP_ORIGIN=http://localhost:3000`. Не отправлять файл в GitHub.
3. Если PostgreSQL уже есть, использовать его адрес. Для Docker: запустить Docker Desktop, задать `POSTGRES_PASSWORD` в окружении терминала, затем `docker compose up -d db`. Указать тот же пароль в локальной строке подключения. Том `bda_pgdata` хранит данные; не удалять его.
4. По желанию поставить `SEED_DEMO=true` **до первой миграции пустой демонстрационной базы**. При false создаётся пустая CRM. Настройка не изменяет уже созданные данные.
5. `npm run db:migrate` - применить схему. Повторный запуск сохраняет записи.
6. Создать сотрудников через команды ниже. Пароль вводится скрыто в терминале, минимальная длина 12 символов. Паролей по умолчанию нет.
7. `npm run dev`, открыть http://localhost:3000.

Для пустой базы:

```sh
npm run employee:create -- ceo@example.test "Руководитель" ceo
npm run employee:create -- sales@example.test "Менеджер" sales
npm run employee:create -- coordinator@example.test "Координатор" coordinator
npm run employee:create -- lawyer@example.test "Юрист" lawyer
```

Для базы, созданной с SEED_DEMO=true, привязать аккаунты к существующим профилям:

```sh
npm run employee:create -- ceo@example.test "Арман Алиев" ceo u1
npm run employee:create -- sales@example.test "Алия Бекова" sales u2
npm run employee:create -- coordinator@example.test "Мадина Кенже" coordinator u3
npm run employee:create -- lawyer@example.test "Данияр Сейтов" lawyer u4
```

Email здесь - идентификатор входа, рассылка не подключена. Для отдельного второго юриста можно привязать профиль u5. Команда не перезаписывает аккаунты с тем же email или профилем.

## Подключение к Vercel

1. Подключить PostgreSQL через Vercel Marketplace (например, Neon) к проекту bda-lawyer-crm. Для текущего этапа использовать только вымышленные данные. Выбор региона и тарифа остаётся за владельцем аккаунта.
2. Проверить наличие `DATABASE_URL` в настройках проекта; использовать строку провайдера с TLS, не отключать проверку сертификата. Не добавлять префикс `NEXT_PUBLIC_`.
3. Указать `APP_ORIGIN=https://bda-lawyer-crm.vercel.app` без завершающего слеша. Для Preview использовать отдельную тестовую базу и origin конкретного окружения; нельзя направлять Preview на рабочую базу.
4. Сохранить подключение к этой базе в локальном `.env.local` (секрет не присылать в чат), выполнить миграцию и создать аккаунты командами выше.
5. В Vercel выбрать Framework Preset **Next.js**, Node.js **22.x**, Build Command **npm run build**, Output Directory оставить по умолчанию для Next.js. Удалить старый override для статического сайта, если он задан.
6. После согласования опубликовать изменения через GitHub. Build не выполняет миграции и не создаёт сотрудников автоматически.
7. После развёртывания проверить вход отдельно для каждой роли, общий сценарий передачи, конфликт параллельных изменений, доступы и выход. Наличие успешной сборки не заменяет эти проверки.

Официальная информация: https://vercel.com/docs/marketplace-storage и https://vercel.com/marketplace/neon.

## Совместимость с прототипом

Прямое открытие `index.html` сохраняет прежний локальный демо-режим. Серверный запуск через Next.js использует `/api/*` и не импортирует localStorage. Перенос старых локальных записей должен быть отдельной контролируемой операцией; текущая реализация их не удаляет и не отправляет на сервер.

## Доступы через CEO (локальная реализация 13.11.2026)

Перед развёртыванием этой версии применить `db/003_employees.sql` штатной командой миграции после резервного копирования. Старые email остаются действующими логинами; новые логины не требуют почты. В «Сотрудники» CEO создаёт доступ, передаёт временный пароль лично, сотрудник меняет его при первом входе. При потере показанного пароля используется «Сбросить пароль». Почтовая доставка не требуется.

Проверки: `node --test tests/employees.test.cjs` и `node --env-file=.env.local tests/employees-api.cjs`. Вторая команда обращается к Neon и создаёт отдельную временную схему с синтетическими аккаунтами; схема удаляется в finally. Не запускается автоматически с обычными тестами. Она проверяет создание, первый вход, обязательную смену пароля, запрет управления для юриста, отключение доступа и отзыв сессий.
