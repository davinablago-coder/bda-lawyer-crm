# BDA Lawyer — интерактивный прототип CRM

План продукта, разделы, user flow четырёх ролей, матрица доступа и этапы разработки: [docs/PRODUCT_PLAN.md](docs/PRODUCT_PLAN.md). Инструкции для дальнейшей разработки: [AGENTS.md](AGENTS.md).

## Открытие

Откройте `index.html` в браузере. Прототип не требует установки библиотек или сборки. Если просмотр локальных файлов запрещён вашим браузером или localStorage недоступен, запустите локальный сервер из папки проекта:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Адрес для ручного открытия: http://127.0.0.1:8080. Остановить сервер: Ctrl+C. Это сервер для локального просмотра, не для production. Данные привязаны к браузеру и origin: `file://` и `http://127.0.0.1:8080` имеют разные локальные хранилища.

## Что можно пройти

1. В верхнем переключателе выберите менеджера. CRM → «Новый лид»: внесите вымышленный запрос и следующий шаг.
2. Откройте карточку, заполните результат квалификации и выберите координатора. Нажмите «Квалифицирован · передать координатору».
3. Переключитесь на координатора. CRM → «Передача и согласование»: задайте стоимость и обоснование, отправьте CEO. От CEO откройте заявку и утвердите сумму либо верните с комментарием. Затем от координатора откройте дело, выбрав юриста и срок. Новая версия суммы требует повторного одобрения. Для быстрого знакомства можно начать с уже переданного лида «Алия Нурова».
4. В деле добавьте задачи и документы в чек-лист; назначьте исполнителя. Во вкладке «Оплаты» запланируйте платёж.
5. Переключитесь на назначенного юриста. Он видит закреплённое дело, выполняет свои задачи, обновляет этап, отмечает получение документов и пишет комментарии.
6. От координатора учтите частичное поступление по платежу. Остаток и статус пересчитаются. CEO видит изменения в Dashboard и аналитике.
7. В разделе «Календарь» переключайте месяц/неделю/день, фильтруйте тип и сотрудника. Добавляйте встречи и суды, открывайте связанные дела и завершайте задачи. Время показывается по Алматы.
8. Для просмотра демонстрационного входа нажмите кнопку выхода внизу боковой панели.

## Границы прототипа

- Все начальные имена, контакты и дела синтетические. Не вводите реальные персональные данные.
- Данные сохраняются только в localStorage текущего браузера. Нет серверной базы, совместной работы и резервных копий.
- Переключение роли — демонстрация сценариев, не авторизация. Пользователь устройства может прочитать локальные данные и изменить роль.
- Документы представлены чек-листом; реальные файлы не загружаются. Учёт оплаты не выполняет банковский перевод.
- Нет подключения сайта, WhatsApp, почты, GitHub или Hoster; нет реальных приглашений сотрудникам.
- Аналитика вычисляется за всё время из локальных записей. Суммы в прототипе — целые тенге. В production денежный тип и округление фиксируются в схеме базы.
- Канбан управляется через карточку и выбор этапа; перетаскивание не реализовано.

## Проверки

```sh
node --check assets/calendar-model.js
node --check assets/model.js
node --check assets/app.js
node --test tests/*.test.cjs
```

Проверяются передача и отсутствие дублей, повторное обращение существующего клиента, ограничения ролей, обязательная причина отказа, частичные поступления и переплата, закрытие дела, переназначение задач, чек-лист, комментарии и безопасный вывод текста. Рендер проверяется в минимальном DOM-стенде Node; это не тест реального браузера и не визуальная проверка.
